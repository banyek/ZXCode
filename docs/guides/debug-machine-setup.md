# Optional ZRCP machine backend

ZXCode's host-side `@zxcode/runner` API now supports the portable machine contract
with a separately installed ZEsarUX 13.0 backend. This is machine control; BASIC
source breakpoints/inspection UI are separate features. Normal Run Spectrum uses
Fuse independently and needs no debugger setup.

Owned launch currently supports Unix hosts and requires an absolute executable
with a real `--remoteprotocol-loopback-only` option. Stock 13.0 is refused before
launch. The optional [source patch](../../scripts/research/zesarux-13-loopback-option.patch)
adds that option to pinned upstream commit
`0bb4277d714128311d78bc0625fb12ae8308899a`; apply it at the release root with
`patch -p1` and build upstream normally. ZXCode downloads/installs/bundles no
emulator or ROM. The adapter checks version/help and always passes the bind flag.
The earlier research-only hardcoded-loopback patch is not this capability option.

After `npm run build`, host code can import `createZrcpBackend` from
`@zxcode/runner`, configure `{executable: "/absolute/path/to/zesarux"}`, and call
`open({mode:"launch",requiredFeatures:["memory-read"]})`. Check structured results,
obtain the current token through `pause()`, and use that exact token for `inspect`,
`resume`, `step`, writes/reset or Z80 snapshot loading. Subscribe to stopped events
for fresh tokens. Close the session and await `finished` when done.

For an existing explicitly chosen local listener, configure `attachPort` and
optionally `attachPrompt` (default `command`), then `open({mode:"attach"})`.
Connections go only to 127.0.0.1. Attach creates no listener and does not establish
how that existing server was bound. It pauses initially, advertises a weaker
inspection/step/pause/resume set, and never terminates the external emulator.
Detach preserves its current logical paused/running state. Global breakpoint,
reset, image-load and write operations are restricted to owned launch sessions.

Owned machine PC breakpoints, RAM/register writes with readback, reset, `.z80`
snapshots and proven native TAP smartload are supported. Portable predicate
conditions and Windows owned launch are not advertised. Read the negotiated register lists and limits;
unknown operations receive `unsupported-operation`. This is a versioned 13.0
protocol implementation. Source/build correlation must be re-attested after
reset/load/writes/reconnect and may refuse runtime-mutated program images.

The reproducible real adapter probe uses a fresh evidence directory:

```sh
node scripts/research/verify-zrcp-adapter.mjs --executable /absolute/patched/zesarux --snapshot /absolute/research/start.z80 --output-dir /absolute/new-evidence
```

The snapshot is generated by the source-correlation research procedure in design
064. The probe checks original-ROM memory, machine breakpoints/stepping, coherent
inspection, reset, restart, actual attach and ownership. Normal CI uses fake
loopback protocol servers; it requires no emulator, ROM or external network.

## BASIC source debugging in VS Code

Set `zxcode.debug.executable`, open a saved local independent BASIC program and run
**ZXCode: Debug Spectrum BASIC**. A trusted workspace is required. A `zxcode-basic`
launch configuration may specify `program`, optional `zesaruxExecutable`, and
`stopOnEntry` (default true). Untitled/non-file native source UI is not advertised in this stage.
The current dirty editor text is compiled to a private
autostart tape; normal build output is not changed.

Use native line breakpoints, or statement-column breakpoints at a command on a
colon/IF tail. Unexecutable rows are unverified rather than moved. The native
current frame identifies the real BASIC line/statement and checked source range.
Loader and syntax hits are not shown as source stops. Continue/Pause work;
a machine pause between statement boundaries may have no mapped source frame.
Changing/closing/reopening the source stops that debug association; restart to
rebuild. Completion is a ROM report, not an invented next-statement source frame.

This exact-image stage does not support runtime-mutated FN slots, self-modifying
programs, alternate ROMs, conditional/log breakpoints, Step Over or Step Out. Such
cases refuse mapping or the unsupported operation. Scope/watch features are
separate from the raw machine contract. The optional original-ROM native probe
runs with `ZXCODE_TEST_ZESARUX` pointing to the required executable when invoking
`npm run test:vsix`; ordinary CI uses no emulator or ROM.

Step Into resumes to the next attested BASIC dispatch, including colon statements,
executed IF tails, loop iterations and GO SUB/RETURN. It requires a verified
paused source location. **ZXCode: Reset BASIC Debug Session** closes the owned
machine and cold-launches the current source in a fresh session, stopping at
entry with cleared variables. Native breakpoints are rebound normally.

Paused scopes include scalars, arrays and FOR state. Watch supports variable
names and fully indexed numeric arrays with positive decimal integer literal
indices; arbitrary expression execution and string slices are unavailable.
**ZXCode: View Memory** opens a read-only paused hex snapshot.
**ZXCode: Show Spectrum Screen** reads the 6912 display bytes through DAP, offers
two static flash phases, and clearly labels historical retained pixels. Refresh
requires a paused machine. See [run guide](run-spectrum.md) for these controls.
