# M1 TAP container contract

M1-09 writes bytes, not BASIC syntax. All metadata is required: exactly ten
already encoded filename bytes, an unsigned 16-bit autostart parameter, and the
offset of variables within the supplied program/data bytes. Filename encoding,
padding, CLI defaults, and program representability remain upstream concerns.
This does not settle the open source-format or autostart-default questions.

## Evidence

- [ROM SAVE header construction](https://skoolkid.github.io/rom/asm/0605.html),
  0625–0650 and 0716–0756: type zero, ten-byte name, data length, autostart word,
  and program length/variables offset. Words are stored low byte first. LOAD disables autorun when either bit 14
  or bit 15 is set (see the M3-07 LOAD evidence below); callers may use 8000h.
- [ROM SAVE control](https://skoolkid.github.io/rom/asm/0970.html), 0986–099E:
  seventeen header bytes followed by the program/data block.
- [ROM SA-BYTES](https://skoolkid.github.io/rom/asm/04C2.html), 04F6–050F:
  flag 00h/FFh and XOR parity including the flag.
- [libspectrum TAP implementation](https://github.com/fuse-emulator/libspectrum/blob/master/tap.c),
  `internal_tap_read` and `write_tap_block`: a little-endian 16-bit block length
  precedes flag/data/parity, excluding the length prefix itself.

The TAP payload limit is therefore 65533 bytes after reserving flag and parity.
This is a container bound, not a promise that such a program fits 48K memory.
The variables offset cannot exceed the supplied data length. Inputs are copied;
the returned byte array belongs to its caller. The writer never parses BASIC.

## Independent unit fixture derivation

`tests/tap.test.mjs` uses synthetic opaque payload `01 02 03`; it deliberately
does not claim those bytes form a valid BASIC program. Its filename is `58`
followed by nine `20` bytes, data length is `03 00`, autostart `00 80`, and
variables offset `02 00`. Header parity is `F9`: the filename XOR is `78`, then
`78 XOR 03 XOR 80 XOR 02 = F9`. Data parity is `FF XOR 01 XOR 02 XOR 03 = FF`.
Thus the block lengths are `13 00` and `05 00`. The literal expected bytes were
derived from these documented fields, not generated by ZXCode. M1-11 still owns
the independent real-program golden fixture and emulator acceptance.

## M3-07 metadata and container hardening

The original ROM [LOAD control at 0808](https://skoolkid.github.io/rom/asm/0808.html),
089B..08A9, tests the high autostart byte with C0h. Either bit 14 or bit 15 disables
autostart, so the enabled raw word range is 0000h..3FFFh. The earlier bit-15-only
description was incomplete. All 16-bit words remain representable metadata;
readers preserve the raw word and report its enabled state without inventing a
1..9999 container restriction. The CLI's deliberate explicit-line policy and
8000h default remain unchanged. Independent ROM fragment probes check both bits
and boundary values before any reader interpretation is implemented.

TAP block parsing is separate from BASIC language/import parsing. A generic reader
accepts a sequence of complete flag/payload/parity blocks with arbitrary flag
bytes, checking little-endian lengths, minimum flag+parity size and XOR parity.
It fails deterministically with structured byte-offset issues for truncated length
prefixes, short/truncated blocks and checksum mismatches; it never resynchronizes,
pads or silently repairs input. Empty generic containers are valid empty sequences.

A stricter BASIC-pair reader accepts exactly one type-zero header/data pair: header
flag 00, seventeen header payload bytes, data flag FF, advertised data length equal
to actual payload, and variables offset no greater than that payload length.
Multiple files/other layouts are reported as unsupported by this convenience
reader, not declared invalid TAP by the generic reader. Payload is opaque and may
include variables; BASIC lines are not parsed here. These readers supply the
validated container foundation for the separate M3-08 import spike.

Names are ten opaque encoded bytes at container level. The CLI now uses the shared
printable Spectrum character map, including £/©/↑ and the existing caret alias,
then explicitly pads to ten bytes. It does not apply source escapes to flags or
transliterate unsupported Unicode. Core writers/readers copy caller buffers;
returned metadata and payload buffers own their data, including Buffer inputs.

Independent fixtures use Python struct field packing and explicit flag-inclusive
XOR, separate from ZXCode. They cover raw names, empty payload, byte/word order,
autostart boundaries, variables offsets, opaque flags and maximum block sizes.
Reader/writer round trips supplement those expected bytes, not replace them.
Original BASIC/TAP golden fixtures remain unchanged.

Validation: all 200 Node 24 checks pass, including byte-exact independent images,
maximum payload boundaries, malformed containers and owned Buffer snapshots.
The standalone fixture verifier and ten original-ROM autostart probes pass without
rewriting reference data.
