# Textual byte escapes (M3-05)

## Selected contract

Escapes are tooling notation for original Spectrum bytes, active only inside
quoted string content and REM tails. They are not new BASIC expression syntax.
No global preprocessing, keyword replacement or backslash escaping is permitted.

| Form | Exact byte representation |
|---|---|
| `{BYTE 0xNN}` | One byte, exactly two hexadecimal digits |
| `{UDG A}` .. `{UDG U}` | 90h..A4h, per design 027 |
| `{BLOCK 0}` .. `{BLOCK 15}` | 80h..8Fh quadrant mask, per design 027 |
| `{INK n}` .. `{OVER n}` | Corresponding control 16..21 and one byte n |
| `{AT row,column}` | 22, row byte, column byte |
| `{TAB position}` | 23, low byte then high byte of position |
| `{COMMA}`, `{EDIT}`, `{LEFT}`, `{RIGHT}`, `{DOWN}`, `{UP}`, `{DELETE}`, `{ENTER}` | Corresponding zero-parameter control |
| `{{` / `}}` | Literal opening / closing brace |

Names/hex digits accept ASCII case differences. ASCII spaces/tabs may pad the
inside of braces and separate names/arguments; AT also permits them around its
comma. Decimal arguments are unsigned, without leading zeros except zero itself.
Control/AT bytes are 0..255; TAB is 0..65535. Raw BYTE requires its 0x prefix and
two digits. There are no expression-valued arguments, decimal fractions, signs,
Unicode digits or guessed glyph aliases. Canonical export uses uppercase names,
uppercase hex digits after lowercase `0x`, one space and no comma padding.

Unknown names, missing/extra parameters, bad byte forms and unmatched/single
braces produce syntax diagnostics with retained error parts. Removing diagnostics
cannot promote those parts into buildable content. Literal braces must now be
doubled, including text that resembles an escape. Backslashes remain literal:
`\n`, `\xFF` and repeated backslashes do not acquire C-style semantics.

## Context, framing and source model

The lexer parses escapes as source-ranged literal/atom/error parts while scanning
strings. REM uses the same component over its already preserved raw tail. It does
not parse quotes/colons as statements. Parts retain exact UTF-16 ranges; escaped
quotes still use authentic doubled-quote syntax. Plain source `value` is available
only when all parts have textual identities; Spectrum byte vectors/atoms are the
authority for strings containing controls, UDGs or raw token bytes. No invented
Unicode carrier character represents an unknown byte.

The original ROM S-QUOTE scanner requires every literal quote data byte to be
doubled, including a quote byte used as a control parameter. The encoder retains
that authentic framing. Byte 13, even in a control payload, terminates a quoted
literal in the original ROM and is therefore a compatibility error in source
string escapes. Use ordinary BASIC `CHR$ 13` concatenation or PRINT AT syntax
where appropriate. No silent expression synthesis is performed. All 256 byte
values, including 13, are supported in REM raw content.

A source formatter operates on M3-03 atoms and emits escaped content for a chosen
string/REM context. It doubles literal braces and string quotes, emits exact
named/raw packets and reports unrepresentable string bytes. REM quotes stay
single raw bytes. To permit exact comments with no leading space, an initial
ASCII letter/digit/$ is emitted with BYTE notation, so concatenating the content
after REM cannot accidentally form a longer keyword/name. No extra comment space
or parameter byte is inserted.

## Fixture-first evidence and migration

Before activation, `escapes-rom.json` records 281 original-ROM statement/framing
observations: every raw byte in a string, named packets, quote-valued parameters,
literal braces/backslashes, and all 256 bytes within a REM tail. Input program
bytes were assembled independently from documented byte identities and quote
framing, then checked in the pinned ROM. They are not generated by ZXCode.
Byte-13 string cases fail in the ROM; quote doubling and arbitrary REM data pass.

Source forms that previously used literal braces now spell them with doubled
braces. Existing expected BASIC/TAP bytes remain unchanged. Where a fixed corpus
source needs this notation migration, its original comparison-tool source is
retained separately as `comparisonSource`; zmakebas does not implement these
source escapes. Unmodified comparison images and primary-reference corrections
remain separately verifiable. New expected bytes must never be rewritten merely
to agree with the implementation.

This contract freezes source transport after the independent byte corpus. M3-06
still audits further lexical combinations; M3-08 still owns BASIC/TAP import and
must surface malformed/unsupported strings rather than lose or repair their bytes.

## Observed validation

The full Node 24 check passes 186 tests, including all 281 original-ROM framing
cases, every single-byte source round trip, all 37 graphics identities, dense
all-byte REM content, malformed escape recovery and unchanged existing goldens.
The original comparison corpus still verifies via its retained comparisonSource.

On 2026-10-17, examples/escapes.bas built through the real CLI and loaded/ran in
the pinned original 48K ROM with fast loading and loader acceleration disabled.
It verified numeric CODE results for UDG A, block 15 and a quote; skipped a REM
containing raw 00/0D/FF bytes; printed ESCAPES OK with embedded colour controls;
and returned ERR_NR=FFh / screen report 0 OK, 40:1 at ROM 0x12AC.
